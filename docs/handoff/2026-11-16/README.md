## Как работать

| Что                           | Как                                                                                                                                                                                                                                                |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Взять задачу                  | `scripts/agent.sh next <дорожка>` → `show <N>` → `start <N>`; одна issue — одна ветка `feat/<N>` — один PR                                                                                                                                         |
| Перед PR                      | `npm run check`; для экранов ещё `npm run e2e`                                                                                                                                                                                                     |
| Ревью                         | Субагент `reviewer` на каждый PR. Для контрактов, `src/core/sync/`, `src/core/account/` и `infra/` — три независимых проверяющих (границы и таблицы; потеря данных и конфликты; безопасность и секреты) и отдельная перепроверка каждого замечания |
| Слияние                       | Зелёный CI и ревью без блокеров и важных замечаний → `scripts/agent.sh merge <PR>`                                                                                                                                                                 |
| Отложенное замечание          | Новая issue в тот же день                                                                                                                                                                                                                          |
| Тесты инфраструктуры локально | Нужен Docker: в облачной сессии `dockerd` запускается вручную в фоне; образы тянутся с Docker Hub, при отказе 429 повторить                                                                                                                        |
| Тесты входа на настоящем Auth | `infra/supabase/tests/account.test.sh`, `otp-attempts.test.sh`, `deploy-remote.test.sh`                                                                                                                                                            |

## Уроки этой сессии

- Работа дважды обрывалась из-за лимита использования. Всё, что не записано в issue, PR или ветку, терялось. Записывай
  находки ревью в PR сразу, а не в конце раунда.
- Замечание ревьюера о безопасности нельзя ни принимать, ни отклонять на слово. Все три важных замечания по #278
  подтвердились на настоящем стеке, а два предложенных ревьюерами исправления оказались неверными: настройка прокси
  не закрывала IPv6, готовый плагин ограничения частоты считал с опозданием.
- Исправление по безопасности само нуждается в ревью: счётчик попыток из второго раунда можно было вытеснить из
  памяти. Это нашёл только третий раунд.
- Клиентский код аккаунта проверен на сервере в памяти, сервер — скриптом. Друг с другом они не запускались ни разу.
  Первая встреча — интеграционный тест в #279 и тест в #287.
