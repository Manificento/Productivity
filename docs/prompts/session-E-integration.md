# Сессия E — интеграция (запускать после того, как A–D открыли PR)

Ты — интеграционный инженер LifeOS и владелец контракта (`src/core`, `src/ui`, `src/app`, конфиги).
Работай автономно; решения записывай в `docs/progress/integration.md`.

## Шаги
1. Прочитай `CLAUDE.md`, `docs/SPEC.md`, `docs/PLAN.md`, все `docs/progress/*.md` и `docs/contract-requests/*.md`.
2. Список открытых PR: `gh pr list`. Сливай по порядку **D → A → B → C**. Для каждого:
   - проверь, что PR не правит файлы вне своей зоны (см. таблицу владения в `CLAUDE.md`);
     нарушения перенеси в запрос контракта или аккуратно реши сам как владелец контракта;
   - подтяни `main`, разреши конфликты, `npm run check` → только зелёным сливай в `main`.
3. Рассмотри запросы контракта: принятые — внеси (новая версия схемы Dexie, если нужен индекс),
   отклонённые — объясни в файле запроса.
4. Сквозная проверка (`npm run dev`, мобильный вьюпорт 360×740 в браузере, если доступен):
   создать экзамен через 5 дней с проектом «Английский» → в «Задачах» фокус-проект наверху,
   в Pomodoro норма выросла, в «Здоровье» цель сна 8 ч и ограничение тренировки, на «Сегодня» причины.
   Импорт/экспорт работают со всеми новыми данными. Офлайн после первой загрузки (сборка + `npm run preview`).
5. Единообразие: русские тексты, тёмная тема, кнопки ≥ 44 px, пустые состояния, нет горизонтальной прокрутки.
6. Обнови `README.md`: что это, как запустить, как задеплоить на Cloudflare Pages или Netlify
   (сборка `npm run build`, папка `dist`), как поставить на телефон как приложение.
7. Итог в `docs/progress/integration.md`: что работает, что нет, топ-5 следующих шагов по `docs/SPEC.md` (P1).

## Готово, когда
`main` содержит все модули, `npm run check` зелёный, сквозной сценарий из шага 4 проходит.
