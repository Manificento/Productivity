# LifeOS — спецификация MVP блока «Продуктивность»

Версия 0.2 · 2026-11-04 · владелец продукта: Petram · решения интервью — [product-decisions.md](product-decisions.md)

## 1. Зачем это приложение

Супер-приложение, которое со временем покрывает все этапы жизни. Первый блок — продуктивность.
Главное преимущество — **общие данные между блоками**: сон, еда, тренировки, задачи и время лежат
в одной базе, поэтому приложение может перестраивать режим целиком, а не по одному трекеру за раз.

Уникальная функция MVP — **слой адаптации**: пользователь отмечает важное событие (экзамен,
дедлайн, собеседование), и все блоки заранее перестраивают нагрузку, сон, питание, тренировки и
восстановление.

**Позиционирование:** «LifeOS готовит тебя к важному событию: сам перестраивает задачи, сон, тренировки и фокус».
Два отличия от конкурентов: **план от события** (планирование назад от экзамена или дедлайна, а не реакция на
сегодняшнее состояние, как у Oura/Whoop) и **действие, а не совет** (приложение меняет все блоки сразу, а не
показывает корреляции, как Bearable).

**Первая аудитория:** люди в саморазвитии, которые уже трекают сон, еду, тренировки и привычки.

**Главное ограничение интерфейса:** обязательный ввод данных — **не больше 3 минут в день**, одним утренним
потоком (сон → чек-ин → тест внимания). Еда и тренировки — по желанию.

## 2. Платформа и принципы

- **PWA — этап проверки идеи**: открывается в браузере на телефоне и ноутбуке, ставится на домашний экран, работает офлайн.
  Дорожная карта: PWA → нативное приложение с Health Connect/HealthKit и облаком → собственный трекинг сна по датчикам.
- **Local-first**: все данные хранятся на устройстве в IndexedDB (Dexie). Сервера и аккаунтов в MVP нет.
  Защита от потери данных — экспорт/импорт JSON.
- **Язык интерфейса**: русский. Код, имена и комментарии — английский.
- **Своя реализация**: код других приложений не копируем, берём только идеи функций.

## 3. Блоки MVP и источник вдохновения

| Модуль      | Аналоги                             | Что делаем в MVP                                                                     |
| ----------- | ----------------------------------- | ------------------------------------------------------------------------------------ |
| `tasks`     | Todoist, Do It Now                  | Задачи, проекты, приоритеты, сроки, повторы, быстрый ввод на естественном языке      |
| `habits`    | Do It Now, трекеры привычек         | Привычки с расписанием, отметки, серии (streaks)                                     |
| `time`      | Time Balance                        | Учёт времени по категориям, фокус-таймер (Pomodoro), баланс за день/неделю           |
| `health`    | MacroFactor, FatSecret, Sleep Cycle | Ручной журнал сна, еды (КБЖУ), тренировок; поиск продуктов через Open Food Facts     |
| `cognition` | Lumosity, Elevate (будущий блок)    | Тест внимания PVT (1 мин) — объективная мера состояния для персонализации            |
| `today`     | — (своё)                            | Важные события, фазы подготовки, ежедневные цели, онбординг, утренний экран, инсайты |

### Честные границы MVP (что НЕ делаем сейчас и почему)

- **Трекинг сна по датчикам** (как Sleep Cycle) — нужен нативный доступ к микрофону/акселерометру в фоне. PWA так не умеет. В MVP — ручной ввод времени отбоя/подъёма и качества.
- **Будильник, который гарантированно разбудит** (как Alarmy) — PWA не может надёжно звонить при закрытом приложении. Отложено до нативной версии.
- **База продуктов уровня FatSecret** — лицензионная. Используем открытую Open Food Facts + свои продукты.
- **Нейротренажёры** (Lumosity/Elevate) и **медитации с аудио** — отдельные большие блоки, P2.
- **Синхронизация между устройствами, аккаунты, AI-коуч** — требуют бэкенда, P2.

## 4. Функции и приоритеты

**P0 — делаем в первом ночном прогоне**

1. Задачи: CRUD, проекты, приоритет 1–4, срок (дата и время), повторяющиеся задачи, теги, архив выполненных.
2. **Быстрый ввод на русском**: `завтра 9:00 позвонить научнику #учёба !1` → срок, проект, приоритет. Работает и по-английски для дат (`tomorrow`, `mon`).
3. Привычки: расписание (ежедневно / дни недели / N раз в неделю), отметка за день, серия, процент выполнения.
4. Учёт времени: старт/стоп таймера по категории, ручная запись, итоги дня и недели по категориям («баланс»).
5. Фокус-таймер (Pomodoro 25/5, настраиваемый), привязка к задаче; сессии пишутся в учёт времени.
6. Журнал сна: отбой, подъём, качество 1–5 → длительность сна.
7. **Онбординг**: первый вопрос — ближайшее важное событие; сразу план на 10 дней (адаптация с первого дня).
8. Журнал тренировок: тип, длительность, интенсивность (RPE 1–10), упражнения/подходы опционально.
9. **Утренний экран за 3 минуты**: сон + чек-ин (энергия, фокус) + переход к тесту внимания и обратно.
   9a. **Тест внимания PVT** (1 минута): время реакции, пропуски, история результатов.
10. **Слой адаптации** (раздел 5) + экран «Сегодня», где видны цели дня из всех блоков.
11. Экспорт/импорт всех данных в JSON.
12. Офлайн-работа, установка как приложение, тёмная тема.

**P1 — следующий прогон**

12a. Журнал еды (по желанию): продукты, граммы, КБЖУ; поиск в Open Food Facts; свои продукты.
12b. Импорт истории из других приложений (Todoist, Sleep Cycle CSV) — нужны реальные файлы экспорта. 13. Инсайты по связям между блоками: сон ↔ выполненные задачи, сон ↔ фокус-минуты, тренировки ↔ энергия. Это и есть главное преимущество общих данных. 14. Еженедельный обзор (weekly review): что сделано, что перенести, баланс времени. 15. Матрица Эйзенхауэра как вид задач. 16. Цели → проекты → задачи (иерархия). 17. Вода, кофеин (с отсечкой по времени). 18. Напоминания через уведомления браузера (на iOS ограничены).

**P2 — позже**

19. Синхронизация и аккаунты (бэкенд).
20. Нейротренажёры, медитации с аудио.
21. Интеграция с носимыми устройствами, нативное приложение (датчики сна, будильник).
22. AI-коуч, который объясняет инсайты и предлагает план.
23. **Персонализация с эластичными границами**: научная норма как априорное распределение, данные человека её
    сдвигают; изменения предлагаются, человек подтверждает. Исходы: самооценка, поведение, тест внимания, результаты событий.
24. Freemium: трекеры и ограниченные инсайты бесплатно, полная система по подписке.

## 5. Слой адаптации (ядро продукта)

### 5.1 Важное событие (`LifeEvent`)

Поля: название, тип (`exam`, `deadline`, `interview`, `competition`, `travel`, `other`), дата и время,
важность 1–3, связанный проект задач (опционально), сколько дней готовиться (по умолчанию 7).

### 5.2 Фазы

| Фаза       | Когда         | Смысл                                                              |
| ---------- | ------------- | ------------------------------------------------------------------ |
| `prep`     | от T−N до T−2 | подготовка: больше фокуса на связанном проекте, режим сна стабилен |
| `taper`    | T−1           | разгрузка: лёгкий день, ранний отбой                               |
| `event`    | день T        | день события                                                       |
| `recovery` | T+1           | восстановление                                                     |
| `normal`   | всё остальное | обычный режим                                                      |

### 5.3 Цели дня (`DailyTargets`) — общий контракт для всех блоков

Один чистый движок `computeDailyTargets(date, context)` возвращает цели на день. Каждый модуль
**читает** их и показывает у себя; ни один модуль не придумывает свои правила адаптации.

- задачи: ёмкость дня в минутах, фокус-проект, можно ли переносить задачи P3–P4;
- сон: целевая длительность, целевое время отбоя;
- тренировки: максимальная интенсивность (`rest`, `light`, `moderate`, `hard`);
- фокус: число Pomodoro на фокус-проект;
- медитация: минуты;
- питание: отсечка кофеина, «без новых продуктов»;
- `reasons[]`: человекочитаемые причины каждой подстройки («Экзамен через 3 дня: +2 фокус-сессии»).

### 5.4 Правила (декларативные, расширяемые)

Правила хранятся как данные (`AdaptationRule[]`), а не как `if` в UI. В MVP:

1. Фаза события меняет цели (таблица в `src/core/adaptation/rules.ts`).
2. Сон прошлой ночи < 6 ч → ёмкость дня −20%, интенсивность тренировки не выше `light`.
3. Энергия в чек-ине ≤ 2 → ёмкость дня −20%.
4. Несколько событий сразу → берётся событие с наибольшей важностью, при равенстве — ближайшее.

Важно: это рекомендации режима дня, а не медицинские советы. В интерфейсе цели показываются
как предложения, их можно переопределить.

## 6. Критерии готовности MVP

- Все P0-функции работают офлайн после первой загрузки.
- `npm run typecheck`, `npm test`, `npm run build` проходят без ошибок.
- Движок адаптации покрыт тестами для каждой фазы и каждого правила.
- Парсер быстрого ввода покрыт тестами (не меньше 20 примеров на русском).
- Экспорт → очистка → импорт восстанавливает все данные (тест).
- Интерфейс удобен на экране телефона шириной 360 px.
