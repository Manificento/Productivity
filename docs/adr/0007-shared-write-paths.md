# 0007. Общие пути записи в `src/core/logging/`

Статус: принято · 2026-11-04 · уточняет [ADR-0002](0002-modular-monolith.md)

## Контекст

Владелец продукта ограничил ежедневный ввод тремя минутами одним утренним потоком «сон → чек-ин → тест»
([product-decisions.md](../product-decisions.md)). Утренний экран живёт в модуле `today`, а таблица сна
принадлежит модулю `health`. По ADR-0002 у каждой таблицы ровно один модуль-писатель, а импорт между
модулями запрещён.

## Решение

- Когда одну таблицу по продуктовой причине заполняют два модуля, единственный путь записи выносится в
  `src/core/logging/` — функция с валидацией (zod) и инвариантами таблицы. Оба модуля вызывают её,
  напрямую в таблицу не пишут.
- Первый такой путь — `saveSleep()` + `sleepWindow()` (одна запись на ночь, `date` = день подъёма,
  отбой позже подъёма на часах = предыдущий вечер).
- Переходы между модулями внутри одного сценария — через маршруты (`/cognition/pvt?return=/`), не через импорты.
- Новый общий путь записи — только через issue `type:contract`.

## Последствия

- ✅ Утренний поток укладывается в один экран, правила владения сохраняются.
- ✅ Валидация сна в одном месте: модули не разойдутся в трактовке «лёг в 23:30, встал в 7:00».
- ❌ `src/core` растёт; держать `logging/` маленьким — только то, что реально пишут два модуля.
