# 0005. Процесс: issue → ветка → PR → CI → ревью → слияние

Статус: принято · 2026-11-04

## Контекст

Разработку ведут ИИ-агенты в облачных сессиях Claude Code, часто без присмотра (ночью).
Нужно, чтобы работа шла маленькими проверяемыми шагами, была видна с телефона и не ломала `main`.

## Решение

- **Источник правды о работе — GitHub Issues.** Каждая issue — пользовательская история с критериями
  приёмки Given/When/Then, метками `area:*`, `type:*`, `priority:*`, `size:*` и вехой (milestone).
- **Trunk-based development**: короткоживущая ветка на одну issue (`feat/<номер>-<slug>`), один PR на issue.
- **Conventional Commits**: `feat(tasks): …`, `fix(core): …`, `test(health): …`, `docs: …`, `chore: …`.
- **Definition of Ready / Done** — в `docs/process.md`; PR-шаблон содержит чек-лист DoD.
- **Независимое ревью**: перед слиянием агент вызывает субагента `reviewer` (`.claude/agents/reviewer.md`),
  который не писал этот код, и исправляет найденное.
- **Слияние**: squash-merge в `main` только при зелёном CI и пройденном ревью. Агент сливает сам через
  REST API (`gh api`), т. к. в облачных сессиях подкоманды `gh pr`/`gh issue` (GraphQL) недоступны.
- **Дорожки (lanes)**: параллельные сессии разделены по меткам `area:*`, поэтому почти не пересекаются.

## Последствия

- ✅ Прогресс виден на GitHub с телефона: закрытые issues, PR, статус CI.
- ✅ `main` всегда зелёный и разворачиваемый.
- ❌ Защита ветки (required checks) на бесплатном плане для приватных репозиториев недоступна —
  дисциплину обеспечивают команда `/ship` и CI. На GitHub Pro или в публичном репо включить
  Branch protection: «Require status checks to pass».
