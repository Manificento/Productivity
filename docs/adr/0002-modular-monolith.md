# 0002. Модульный монолит с проверяемыми границами

Статус: принято · 2026-11-04

## Контекст

Код пишут несколько ИИ-агентов параллельно. Без жёстких границ они правят одни и те же файлы,
создают конфликты слияния и неявные связи между фичами. Супер-приложение будет расти новыми блоками.

## Решение

- Одно приложение, разделённое на модули `src/modules/<id>/`; каждый — вертикальный срез фичи.
- Общее ядро `src/core/` (типы, схема БД со ВСЕМИ таблицами, даты, движок адаптации) — единственная
  точка связи. Модули обмениваются данными через БД, а не через импорты друг друга.
- Оболочка строит роутинг из манифестов модулей: добавление экрана не требует правок оболочки.
- У каждой таблицы ровно один модуль-владелец, который в неё пишет.
- Границы проверяются автоматически (`dependency-cruiser`, `npm run deps`), нарушение роняет CI.
- Изменение ядра — только через issue с меткой `contract` и отдельный PR.

## Последствия

- ✅ Четыре агента работают одновременно почти без конфликтов.
- ✅ Новый блок супер-приложения (финансы, обучение) — новая папка в `modules/`.
- ❌ Иногда приходится дублировать небольшой код чтения чужих таблиц вместо импорта.
- ❌ Изменения контракта медленнее — это осознанная плата за стабильность.
