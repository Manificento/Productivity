# CLAUDE.md — правила для агентов в этом репозитории

LifeOS — local-first PWA, блок «Продуктивность» супер-приложения. Владелец не пишет код руками:
весь код пишут агенты, поэтому код должен быть понятным, проверяемым тестами и не ломать чужие модули.

Перед работой прочитай: `docs/SPEC.md` (что строим), `docs/PLAN.md` (кто что делает), свой промпт в `docs/prompts/`.

## Стек

Vite · React 19 · TypeScript (strict) · Tailwind v4 · Dexie (IndexedDB) + `dexie-react-hooks` ·
react-router (HashRouter) · date-fns · zod · Vitest + Testing Library + fake-indexeddb · vite-plugin-pwa.

Команды: `npm run dev` · `npm run typecheck` · `npm run lint` · `npm test` · `npm run build` ·
`npm run check` (всё сразу — обязателен перед каждым коммитом в main и перед открытием PR).

## Структура

```
src/
  core/            ОБЩИЙ КОНТРАКТ — не менять без запроса (см. ниже)
    types.ts       доменные типы всех модулей
    db.ts          Dexie-схема: ВСЕ таблицы всех модулей уже объявлены
    dates.ts       DateKey 'YYYY-MM-DD' в локальном времени
    ids.ts         newRecord(), touch()
    backup.ts      экспорт/импорт JSON
    adaptation/    движок адаптации: computeDailyTargets() и хук useDailyTargets()
  ui/              мини-кит: Page, Card, Button, Empty
  app/             оболочка: роутинг и навигация из манифестов модулей
  modules/<id>/    фича-модули; каждый экспортирует манифест из index.ts
```

## Правила владения (чтобы параллельные сессии не конфликтовали)

1. **Пиши только в свою папку** `src/modules/<твой модуль>/` и в свой файл `docs/progress/<модуль>.md`.
2. **Пиши только в свои таблицы** БД. Читать можно любые.

   | Модуль | Таблицы (запись) |
   |---|---|
   | tasks | projects, tasks |
   | habits | habits, habitLogs |
   | time | timeCategories, timeEntries |
   | health | sleepLogs, foods, mealLogs, workoutLogs |
   | today (адаптация) | lifeEvents, checkIns, settings с ключами `adaptation.*`; также владеет кодом `src/core/adaptation/` (только добавлять, не ломать) |
   | settings | settings (остальные ключи) |

3. **Не импортируй компоненты других модулей.** Нужны чужие данные — читай таблицу через `db`
   и рисуй свой виджет. Общие для двух модулей функции — это контракт, см. ниже.
4. **Цели дня берутся только из `useDailyTargets(date)`.** Никаких своих правил адаптации в модулях.
   Если модулю нужна новая цель — запрос на изменение контракта.
5. **Даты дней — только `DateKey` через `core/dates.ts`.** Никогда `toISOString().slice(0,10)` (это UTC).

## Изменение контракта (`src/core/`, `src/ui/`, `src/app/`, конфиги)

Не редактируй их сам. Создай `docs/contract-requests/<модуль>.md`: что нужно, зачем, предлагаемый diff.
Пока запрос не принят — обходись своим кодом внутри модуля (например, своё поле в записи
без индекса: IndexedDB хранит любые поля). Интеграционная сессия принимает запросы.

Исключение — интеграционная сессия (`docs/prompts/session-E-integration.md`): она владеет контрактом.
Новый индекс в БД = новая версия `this.version(n+1).stores(...)`, старые версии не трогать.

## Качество

- Логику держи в чистых функциях (`*.ts`) отдельно от компонентов, покрывай их тестами `*.test.ts`.
- Тесты описывают поведение («переносит задачу на завтра»), а не реализацию.
- Компонентные тесты — через Testing Library по ролям и тексту.
- Интерфейс на русском, mobile-first: всё удобно на ширине 360 px, кнопки не меньше 44 px.
- Тёмная тема: используй пары `dark:` как в `src/ui`.
- Никаких сетевых запросов, кроме Open Food Facts в модуле health. Ключей и секретов в коде нет.
- Не добавляй зависимостей без необходимости; если добавил — объясни в `docs/progress/<модуль>.md`.

## Git

- Работай в своей ветке, коммить небольшими логичными шагами, сообщения на английском в повелительном
  наклонении: `tasks: add quick-add parser for Russian dates`.
- Перед финалом: `npm run check` зелёный → push → PR в `main` с описанием и чек-листом SPEC.
- В конце сессии обнови `docs/progress/<модуль>.md`: что сделано, что нет, известные проблемы.
